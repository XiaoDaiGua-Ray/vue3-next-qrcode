# vue3-next-qrcode v4.1.0

`v4.1.0` is the stable release of the v4.1 beta line. It keeps Vue 3.0.1 as
the minimum peer version while strengthening public declarations, composable
control, Nuxt 4 guidance, CSS customization, and asynchronous rendering safety.

## Install

```bash
pnpm add vue3-next-qrcode@4.1.0
```

```bash
npm install vue3-next-qrcode@4.1.0
```

## Highlights

- Vue peer dependency remains `^3.0.1`; development and upper-bound validation
  use Vue `3.5.41`.
- Public declarations no longer leak Vue 3.5-only `Ref<T, S>`, `ShallowRef`,
  `MaybeRef`, or `ExtractPublicPropTypes` shapes.
- `useQRCode({ defaultOptions, concurrency })` adds status tracking, latest-only
  ownership, explicit cancellation, reset, and disposal.
- Cancelled and superseded requests reject with
  `QRCodeGenerationCancelledError` instead of silently returning stale data.
- `defineProvider` now covers container, image, mask, loading, error, and action
  styling. Existing primary and spinner variables remain compatible fallbacks.
- GIF request ownership is race-safe, and `AwesomeQR` component defaults are
  cloned per instance.
- Nuxt 4 documentation uses the `app/` structure, explicit style imports, and a
  stable `<ClientOnly>` fallback.
- CI uses Node 24 and the pnpm version declared by `packageManager`, and runs the
  complete package test command.

## Hooks

The original API remains valid:

```ts
const qr = useQRCode()
await qr.generate({ text: 'Hello' })
```

New control is opt-in:

```ts
import { QRCodeGenerationCancelledError, useQRCode } from 'vue3-next-qrcode'

const qr = useQRCode({
  concurrency: 'latest',
  defaultOptions: { text: 'Hello', size: 240 },
})

try {
  await qr.generate()
} catch (error) {
  if (!(error instanceof QRCodeGenerationCancelledError)) throw error
}
```

`cancel()` preserves the last successful image. `reset()` cancels and clears
public state. `clear()` remains an alias for `reset()`. `dispose()` permanently
stops the hook and is called automatically in a supported Vue scope or component
lifecycle.

## Nuxt 4 And SSR

The root and `/client` entries are safe to import during SSR, but QR rendering
still requires browser Canvas APIs. Put the client component inside
`<ClientOnly>`, provide `#fallback`, and import `vue3-next-qrcode/style.css`
explicitly. Nuxt removes the default client-only slot from the server build, so
component-only CSS may not be inlined into initial HTML.

Official references:

- [Nuxt `<ClientOnly>`](https://nuxt.com/docs/4.x/api/components/client-only)
- [Nuxt 4 upgrade guide](https://nuxt.com/docs/4.x/getting-started/upgrade)
- [Vue core changelog](https://github.com/vuejs/core/blob/main/CHANGELOG.md)

## Breaking Changes

- Browser binary results use `Uint8Array` instead of Node `Buffer`.
- `downloadQRCode()` returns `Promise<void>`.
- Invalid `version`, `maskPattern`, and `dotScale` values fail validation.
- Internal deep imports not listed in package `exports` are unsupported.

The Vue minimum remains `3.0.1`; it is not a breaking change. See the
[migration guide](./v4.1.0-migration.md) for exact replacements.

## Deferred Work

QR data segmentation, mask-scoring optimization, and packaged worker
reintroduction remain deferred to the next prerelease line. The stable package
continues to use the verified main-thread path.
