# vue3-next-qrcode v4.1.0-beta.0

`v4.1.0-beta.0` is a beta release focused on packaging reliability, Nuxt SSR-safe imports, and QR rendering performance.

## Install

```bash
pnpm add vue3-next-qrcode@beta
```

```bash
npm install vue3-next-qrcode@beta
```

## What Changed

- Root package imports are now SSR-safe. `import 'vue3-next-qrcode'` and `require('vue3-next-qrcode')` no longer initialize DOM, Canvas, or GIF rendering code during server-side import.
- Added `vue3-next-qrcode/client` for explicit client-only component usage in Nuxt and other SSR frameworks.
- Added `vue3-next-qrcode/style.css` while keeping `vue3-next-qrcode/es/style.css` and `vue3-next-qrcode/lib/style.css`.
- Moved QR rendering behind a lazy renderer so normal imports stay light. GIF parsing and GIF encoding load only when GIF rendering is requested.
- GIF rendering now uses the verified main-thread path in packaged builds. The worker path remains disabled until relative worker URLs pass ESM/CJS package smoke tests.
- Replaced the old browser `skia-canvas` shim with a small canvas adapter, removing the `path-browserify` chain from the browser package.
- QR text encoding now uses `TextEncoder`, improving emoji and multilingual text support.
- Rapid prop updates now queue the latest render instead of dropping updates while a render is already running.

## AwesomeQR Fix Details

See [`../awesome-qr-analysis.md`](../awesome-qr-analysis.md) for the detailed optimization and bug analysis.

- Fixed a `gifFrames.forEach(async ...)` bug where async frame work was not awaited before finalizing the GIF.
- Fixed `autoColor` division by zero, which could produce `rgb(NaN,NaN,NaN)` when no non-white/non-black samples were available.
- Removed unconditional browser type exposure of Node `Buffer` from public QR render response types.
- Removed the browser build's fallback return of `Buffer.from(...)`; binary fallback now returns `Uint8Array`.

## Nuxt Usage

```vue
<template>
  <ClientOnly>
    <QRCodeClient text="Hello Nuxt" />
  </ClientOnly>
</template>

<script setup lang="ts">
import { QRCodeClient } from 'vue3-next-qrcode/client'
import 'vue3-next-qrcode/style.css'
</script>
```

The package can be imported during SSR, but QR image generation still requires a browser canvas environment. Keep rendering inside `<ClientOnly>` or an equivalent client-only boundary.

## Package Size Notes

The root ESM entry is now roughly `0.38 kB` uncompressed after `build:lib`. The heavier renderer modules are lazy chunks; GIF parser and GIF encoder are only used when rendering requires them.
