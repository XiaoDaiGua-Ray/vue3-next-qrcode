# v4.1.0 Migration Guide

This guide lists only externally observable v4 changes. Vue `3.0.1` remains the
minimum supported version and is not a breaking change.

## 1. Replace Node `Buffer` Assumptions

Browser binary QR results now use `Uint8Array`.

```ts
// Before
function save(result: Buffer) {}

// v4.1.0
function save(result: Uint8Array) {}
```

String data URLs remain strings. Narrow the union before consuming a result:

```ts
const result = await generate({ text: 'Hello' })

if (typeof result === 'string') {
  image.src = result
} else if (result instanceof Uint8Array) {
  // Handle binary output.
}
```

## 2. Await Downloads

`downloadQRCode()` now returns `Promise<void>`.

```ts
await qrcodeRef.value?.downloadQRCode('qrcode.png')
```

This lets render/download failures propagate through normal async error
handling.

## 3. Fix Invalid Encoding Options

The component validates these inputs before rendering:

- `version`: integer from `1` to `40`;
- `maskPattern`: integer from `0` to `7`;
- `dotScale`: number in `(0, 1]`.

Remove invalid values or clamp them in application code. Omitting `version` and
`maskPattern` keeps automatic selection.

## 4. Use Exported Entrypoints

Only these public entries are guaranteed:

```ts
import { Vue3NextQrcode, useQRCode } from 'vue3-next-qrcode'
import { QRCodeClient } from 'vue3-next-qrcode/client'
import 'vue3-next-qrcode/style.css'
```

Do not import package-internal files such as
`vue3-next-qrcode/es/qrcode/src/...`. Internal layout may change without a
major release because those paths are not in `exports`.

## 5. Nuxt 4 Client Boundary

Place the consuming page under `app/pages/` and use a stable fallback:

```vue
<script setup lang="ts">
import { QRCodeClient } from 'vue3-next-qrcode/client'
import 'vue3-next-qrcode/style.css'
</script>

<template>
  <ClientOnly>
    <QRCodeClient text="Hello Nuxt 4" />
    <template #fallback>
      <div style="width: 160px; height: 160px" aria-label="Loading QR code" />
    </template>
  </ClientOnly>
</template>
```

The placeholder is rendered on the server and remains until the client-only
content mounts. Explicit style import avoids relying on CSS that Nuxt may remove
with the default slot from the server bundle.

## Non-Breaking Additions

- Existing `useQRCode()` and `generate({ text })` calls remain valid.
- Default concurrency remains `reject`.
- `clear()` remains available as an alias for `reset()`.
- Existing `--r-qrcode-primary-color`, `--r-qrcode-primary-color-2`, and
  `--r-qrcode-spin-size` retain their meaning as fallback variables.
- Vue peer remains `^3.0.1`.
