# vue3-next-qrcode v4.1.0-beta.1

`v4.1.0-beta.1` focuses on stabilizing the beta after the first month of runtime feedback. It fixes the highest-risk render and declaration issues, adds reusable hooks, disables the unverified packaged worker path, and adds a broader automated test suite.

## Install

```bash
pnpm add vue3-next-qrcode@4.1.0-beta.1
```

```bash
npm install vue3-next-qrcode@4.1.0-beta.1
```

## What Changed

- `AwesomeQR.draw()` now returns `_draw()` directly, so render failures reject normally and reach component `onError` / cleanup paths.
- `AwesomeQR` initializes canvas size from merged defaults and adds GIF frame-count, dimension, and total-pixel guards.
- GIF output now applies per-frame delays, handles disposal type 2/3, and reuses intermediate canvases where safe.
- `QRCode` and `useQRCode` now share internal latest-only render scheduling and stale GIF URL handling.
- Added `useQRCodeDownload(sourceRef)` and `clearQRCodeGIFCache()` public APIs.
- Public declarations no longer import missing private `core/awesome-qr` declarations.
- `QRCodeInst.downloadQRCode` now correctly returns `Promise<void>`.
- Added validators for `version` `1..40`, `maskPattern` `0..7`, and `dotScale` `(0, 1]`.
- Packaged worker rendering is disabled until relative worker URLs pass ESM/CJS package smoke tests.
- Release workflow now targets npmjs for the unscoped package.

## Test Coverage Added

- `vitest` + `happy-dom` unit tests cover prop validators, `call`, GIF cache/deduplication/clear semantics, `useGifBackground`, `useQRCodeRenderQueue`, `useQRCodeDownload`, `useQRCode`, `QRCode` component async rendering, renderer worker-disable behavior, and core source guard assertions.
- `scripts/smoke.mjs` now verifies package file presence, ESM/CJS/client/style imports, lazy public entries, obsolete dependency references, disabled packaged worker references, declaration consumer smoke, prop validators, core render guards, and emoji QR encoding.
