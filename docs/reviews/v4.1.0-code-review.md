# v4.1.0 Full Code Review

Review date: 2026-08-12

Scope: all source, package entrypoints, declarations, tests, build configuration,
CI workflows, examples, and release metadata in `vue3-next-qrcode`. Generated
ESM/CJS/UMD output is reviewed through source correspondence and package smoke.
The source inventory contains 5,997 lines under `components/` before generated
artifacts.

## Review Method

- Traced root, `/client`, and style exports through ESM and CJS builds.
- Traced component mount/watch/unmount, GIF fetch/cache, render ownership,
  download, and composable state transitions.
- Reviewed QR model, mask selection, Canvas adapter, static image/GIF drawing,
  encoder/parser limits, and disabled worker boundary.
- Compared public declarations with Vue 3.0.1 and current Vue 3.5 declarations.
- Compared Nuxt usage with the official Nuxt 4 `<ClientOnly>` and upgrade docs.
- Searched browser globals, Node `Buffer`, unbounded listeners/timers, async
  loops, shared mutable defaults, stale promise cleanup, and unsupported deep
  imports.
- Exercised validators, state machines, races, build outputs, package exports,
  dependency metadata, and consumer declarations.

## Release-Blocking Findings Resolved

### CR-01: Public declarations leaked Vue 3.5 types

Severity: high.

`ExtractPublicPropTypes`, Vue's exported `MaybeRef`, and generated two-generic
`Ref<T, S>` / `ShallowRef<T, S>` shapes do not exist in Vue 3.0.1. Public props
now use `ExtractPropTypes`, download sources use a local compatible maybe-ref,
hook returns explicitly expose one-generic `Ref<T>` / `ComputedRef<T>`, and both
component entries are narrowed to `DefineComponent<QRCodeProps>`.

### CR-02: Hook work could outlive result ownership

Severity: high.

The original composable only rejected a second call and had no public logical
cancellation or disposal. The new state machine gives every job an owner ID,
rejects superseded jobs with `QRCodeGenerationCancelledError`, blocks stale
commit after cancel/reset/dispose, queues the latest physical render behind an
already-running job, and preserves the last successful result on `cancel()`.

### CR-03: Old GIF `finally` could delete a new request

Severity: high.

Clearing the GIF cache while a request was in flight allowed a new request for
the same URL. The old promise's `finally` then unconditionally removed the new
entry. Cleanup now deletes only when the map still owns that exact promise.

### CR-04: `AwesomeQR` defaults were mutable across instances

Severity: high.

An instance without explicit `components` reused
`AwesomeQR.defaultComponentOptions`. Applying `dotScale` mutated shared nested
objects and changed subsequent instances. Every nested component option is now
cloned and merged per constructor invocation.

### CR-05: CI and Release workflow mismatch

Severity: high.

CI pinned pnpm 10 and Node 20 while `packageManager` declares pnpm 11.9.0. CI now
uses Node 24, lets pnpm/action-setup infer the declared pnpm version, and runs the
complete test command. The credential-less release-triggered npm publisher was
removed to prevent a failing or duplicate publish after the manual release.

### CR-06: Vue 3.0.1 has no `setupContext.expose()`

Severity: high.

The first real-browser minimum-peer test showed that Vue 3.0.1 passes only
`attrs`, `slots`, and `emit` in the setup context. The component now
feature-detects `expose()` and also returns `downloadQRCode` from setup, keeping
the instance method available on Vue 3.0.x while newer Vue versions retain an
explicit exposed surface.

## Compatibility Review

- Vue: no runtime dependency on Vue 3.5-only APIs. Scope cleanup is
  feature-detected; component unmount and explicit `dispose()` remain the
  fallback. Peer minimum remains `^3.0.1`.
- Nuxt 4: root and `/client` imports stay SSR-safe. Canvas work remains inside
  client execution. Examples use `app/`, explicit CSS, and a server fallback.
- Package: only `.`, `./client`, and documented style paths are public. Build
  outputs contain no package-manager-private or obsolete dependency paths.
- Legacy CSS: primary colors and spinner border width keep their original
  semantics as fallback values behind new semantic variables.

## QR Core Optimization Review

No QR encoding algorithm change is included in the stable release. The following
items are valid next-prerelease work, ordered by expected value and risk:

1. Data segmentation: the encoder currently puts all input into byte mode.
   Numeric/alphanumeric segmentation can reduce QR version and render cost but
   requires spec-vector and mixed-segment regression coverage.
2. Mask scoring: all eight masks rebuild/score full module matrices. Hot paths
   use string-keyed `Map` lookups and recreate mask-function tables. Typed row
   storage, direct neighbor access, and preselected mask callbacks should be
   benchmarkable without changing scoring semantics.
3. Worker packaging: the worker source exists but production builds deliberately
   disable it. Reintroduction needs stable relative URLs for ESM/CJS consumers,
   cancellation/timeout ownership, transferable GIF buffers, and fallback tests
   across Vite and Nuxt.
4. GIF output: base64 string construction and full-frame readback create peak
   memory pressure for large animations. Chunked conversion and encoder
   streaming can be explored after maintaining current disposal/delay semantics.
5. Core cleanup: `AwesomeQR._cache` is currently unused. Remove or define a
   bounded, measured cache only in the next core refactor.

These are intentionally deferred from `4.1.0`; changing segmentation, mask
selection, or worker execution at the stable gate would expand correctness and
packaging risk.

## Residual Risk And Gates

- Canvas rendering cannot be meaningfully proven by SSR import alone; the final
  tarball must render in a browser on the Vue 3.0.1 and Vue 3.5.41 consumer paths.
- `<ClientOnly>` fallback and hydration must be checked against the built Nuxt
  server, not only a Vite development server.
- npm and GitHub correspondence must be verified from downloaded remote
  artifacts after publication.

No unresolved release-blocking code finding remains after the documented gates
pass. QR segmentation, mask optimization, and worker refactoring remain tracked
for the next beta line.
